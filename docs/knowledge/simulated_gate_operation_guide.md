# 模拟水闸运行关注要点（仅供演示）

> **重要声明：本文档为本项目自行编写的 simulated / demo 知识材料，不是正式工程规范、行业标准或真实工程运行规程。内容仅用于演示 RAG 检索、引用和 Agent 工具调用，不得用于真实工程调度、安全判断或设备控制。**

## 1. 数据完整性与基础检查

演示分析首先关注时间戳是否连续、采样间隔是否一致、关键字段是否缺失，以及水位、闸门开度和流量的单位是否明确。若出现重复时间戳、长时间缺测、开度超出 0% 至 100% 或无法解释的突变，应先核对数据采集链路，再解释运行现象。

本 Demo 中的基本观测指标包括上游水位、下游水位、闸门开度与流量。对单个异常点不应直接给出设备故障或工程风险结论；统计异常只表示该值偏离所选方法的参考分布，需要结合传感器状态、同期记录和现场背景人工复核。

## 2. 水位变化的演示性关注方法

分析水位时可以同时查看绝对值、变化速率和上下游水位差。连续上升或下降趋势比单个采样点更能描述时段特征，但趋势仍不等同于风险等级。若水位突变而闸门开度、流量均没有相应变化，可优先检查采样、量程、时间同步和数据录入情况。

本演示不设定真实工程的警戒水位、保证水位或变化率限值。此类阈值必须来自可追溯的正式文件和具体工程参数，不能由大语言模型、模拟文档或通用统计规则替代。

## 3. 闸门开度与流量的联合观察

闸门开度调整通常应结合调整前后流量、上下游水位与时间延迟一起观察。开度增大不保证同一采样时刻的流量必然按固定比例增加，因为水头差、测量误差和响应滞后也可能影响观测关系。

相关系数可以描述选定时段内变量的线性共同变化，但相关不代表因果。若需要解释一次明显的开度调整，应先定位调整时段，再对比调整前后的数据，最后回到可追溯的运行记录核验原因。

## 4. 统计异常复核清单

当 Z-score、IQR 或滚动统计检出异常时，演示性复核顺序可以包括：确认时间戳和单位；检查相邻时刻数据；比较其他变量是否同步变化；查看是否对应明显闸门调整；核对传感器或采集系统记录；记录方法、阈值和原始值。

异常算法输出至少应包含异常时间、变量、实际值、异常分数和判断依据。算法结论只作为分析线索，不应表述为真实工程事故、故障诊断、安全结论或自动调度指令。

## 5. 演示日报建议结构

运行日报可展示统计时段、数据点数量、各指标的均值与极值、主要闸门开度变化、统计异常列表、使用的方法与阈值，以及“仅供演示分析”的限制声明。日报中的数值应由 Python 工具计算，语言模型只负责组织和解释工具返回结果。
